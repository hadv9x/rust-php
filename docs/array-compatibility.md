# PHP array compatibility inventory

PHP 8.5 `array_first()` and `array_last()` return the first/last value in insertion order, preserve sparse keys' ordering, return `null` for empty arrays, and leave the array's internal pointer unchanged. Both are supported as direct calls, named-argument calls, and array callbacks. See the [PHP `array_first()` manual](https://www.php.net/manual/en/function.array-first.php) and [PHP `array_last()` manual](https://www.php.net/manual/en/function.array-last.php).

Increment/decrement operators on undefined variables emit a source-located `E_WARNING` and then apply the operator to the resulting `null` value (postfix therefore yields `null`; the variable is initialized to `1`). Increment/decrement of a missing key in an existing array also emits `Undefined array key` and creates that element with the resulting value; this applies to variable-rooted, instance-property, and static-property array paths. Booleans and decrement on `null` retain their values and emit PHP-compatible warnings. Decrementing a nonnumeric string (including the empty string) and incrementing a nonnumeric string emit deprecation diagnostics for the PHP 8.3/8.5 compatibility baseline; incrementing `null` converts it to `1`, while decrementing an empty string produces `-1`. These diagnostics pass through registered custom error handlers with severity and source metadata; handler exceptions propagate into PHP `try/catch`. `error_reporting()` filters warnings/deprecations that are not handled, using `E_WARNING`, `E_DEPRECATED`, or `E_ALL`. Runtime diagnostics retain the active source file and line, which the CLI reports alongside the message. Unsupported array, resource, and object operands raise catchable `TypeError`. See the [PHP Manual](https://www.php.net/manual/en/language.operators.increment.php) and the [Saner Increment/Decrement Operators RFC](https://wiki.php.net/rfc/saner-inc-dec-operators).

This inventory is checked against the official [PHP array function reference](https://www.php.net/manual/en/ref.array.php), [array type documentation](https://www.php.net/manual/en/language.types.array.php), and [array operators](https://www.php.net/manual/en/language.operators.array.php). Compatibility is partial; implemented names do not imply every PHP edge case or warning is reproduced.

## Implemented syntax and behavior

- `[]` and `array()` literals, numeric and string keys, mixed keys, trailing commas, duplicate-key replacement, implicit numeric keys, and common PHP scalar key conversions. Fractional floats used as keys truncate toward zero and emit the PHP 8.1+ precision-loss deprecation in literals, offset reads/writes, nested assignment/destructuring paths, `array_column()`, `array_combine()`, `array_fill_keys()`, and `array_key_exists()`. In the PHP 8.5 baseline, coercing `NAN` warns `unexpected NAN value was coerced to int`, and out-of-range floats warn `non-representable float was cast to int`.
- Array unpacking (`...$array`) with numeric keys reindexed and string keys preserved/replaced.
- Positional, literal-keyed, and nested destructuring with `list()` and short-array syntax, including skipped targets and implicit integer keys after explicit integer keys.
- Destructuring assignments can bind variables, array offsets, and writable untyped object properties by reference (`[$value, &$alias] = $source`, `[&$holder['slot']] = $source`, `[&$object->slot] = $source`), including nested source paths and property array offsets. Updating the target changes the corresponding source slot. Typed/readonly and overloaded-property reference targets remain unsupported and raise catchable errors.
- Under the PHP 8.5 baseline, destructuring a scalar or resource emits `Cannot use TYPE as array` and assigns `null` to each target; destructuring `null` remains silent. Objects continue to raise catchable `Error`. This follows the [PHP 8.5 warnings RFC](https://wiki.php.net/rfc/warnings-php-8-5).
- Read and write nested offsets, append with `$array[]`, `$nested['key'][]`, and mixed nested append/key assignment paths (including committing appended nested paths rooted at `$GLOBALS`), keyed/unkeyed `foreach`, `unset()` on variables and offsets, and array union with `+`.
- By-value array copies; the VM updates the named variable for by-reference mutators. Regression coverage verifies `array_push()`, `array_pop()`, `array_unshift()`, `array_shift()`, and `array_splice()` detach ordinary slots in copied arrays while preserving embedded reference cells. Explicit reference cells survive `array_merge()`, `array_merge_recursive()`, `array_slice()`, `array_reverse()`, `array_replace()`, `array_replace_recursive()`, `array_chunk()`, `array_pad()`, and `array_unique()` copies, including nested reference cells that become elements of a recursive merge result. `array_pop()` and `array_shift()` return dereferenced value copies when removing reference-backed elements, so assigning to the result does not change the former referenced variable. `array_shift()` also keeps reference cells in remaining elements while reindexing numeric keys. `array_splice()` casts a non-array replacement to array values, including object properties, and preserves reference cells carried by replacement arrays.
- `array_column()` reads selected fields from array rows or public properties on object rows, preserves whole rows when `column_key` is `null`, and can index the output by another field.
- `array_values()` and `array_filter()` preserve reference cells embedded in copied array elements; mutating the transformed element updates the referenced variable.
- `array_column()` preserves reference cells for selected values, so writes through the output column update the referenced source variable.
- `count($array, COUNT_RECURSIVE)` counts nested arrays and emits one `E_WARNING` (`count(): Recursion detected`) when a reference cycle is encountered; it returns the partial count without recurring indefinitely.
- `array_walk_recursive()` detects a repeated reference edge, emits one `E_WARNING` (`array_walk_recursive(): Recursion detected`), and skips that edge instead of recursing without bound.
- Ordinary reads of missing keys in an existing array now yield `null` and emit a filtered, source-located `E_WARNING` (`Undefined array key ...`). `isset()`, `empty()`, and `??` use silent offset reads. Nested by-value array copies separate ordinary nested values, while explicit reference cells embedded in arrays remain shared across copies. Mutation coverage is focused; full PHP copy-on-write/reference behavior across every array operation and warning path is not implemented.
- Using an array or object as an array offset key raises a catchable `TypeError` with PHP 8's `Illegal offset type` message for reads and writes. `isset()` and `empty()` raise `Cannot access offset of type TYPE in isset or empty` for invalid array/object keys; with string offsets, they emit the PHP 8.5 warning and return `false`/`true`, respectively. `unset()` raises a catchable `Error` with `Cannot unset offset of type TYPE on CONTAINER`. Missing valid keys stay silent. These diagnostics follow the [PHP 8.5 warnings RFC](https://wiki.php.net/rfc/warnings-php-8-5) and PHP 8.5 regression contract.
- By-reference destructuring can rebind a local that already aliases another variable. The local joins the source element's reference cell, while its former alias remains attached to the old cell; global/static targets and local targets use their respective symbol-table bindings. Array-element and object-property target paths have separate coverage.

## Implemented functions

`array_combine()` throws catchable `ValueError` when the key and value arrays have different lengths, matching PHP 8.0+; the diagnostic names both arguments.

`array_flip()` accepts only integer and string values as output keys. Other values emit one `E_WARNING` each and are skipped; reference-backed scalar values are dereferenced before validation.

`array_count_values()` counts only integer and string values. Each other value emits the PHP warning and is skipped; reference-backed scalars are dereferenced before counting.

`array_change_key_case()` converts only ASCII letters in string keys; integer keys and non-ASCII bytes remain unchanged, matching PHP 8.2 and newer.

`array_chunk()` throws catchable `ValueError` when its length is zero or negative.

`array_fill()` throws catchable `ValueError` for a negative count or a count above PHP's maximum `2147483647`. A positive count whose generated keys would overflow `PHP_INT_MAX` throws the PHP `Error` about the next element already being occupied. Counts above this runtime's one-million-entry allocation guard still raise a catchable `Error` rather than attempting an unbounded allocation.

Destructuring a missing array key emits a filtered `E_WARNING` (`Undefined array key ...`) and assigns `null` to the target. Omitted destructuring positions do not trigger a warning. This follows the [PHP `list()` manual](https://www.php.net/manual/en/function.list.php).

`array_all`, `array_any`, `array_change_key_case`, `array_chunk`, `array_column`, `array_count_values`, `array_fill`, `array_fill_keys`, `array_pad`, `array_combine`, `array_count_values`, `array_diff`, `array_diff_assoc`, `array_diff_key`, `array_diff_uassoc`, `array_diff_ukey`, `array_fill`, `array_fill_keys`, `array_filter`, `array_find`, `array_find_key`, `array_first`, `array_flip`, `array_intersect`, `array_intersect_assoc`, `array_intersect_key`, `array_intersect_uassoc`, `array_intersect_ukey`, `array_is_list`, `array_key_exists`, `array_key_first`, `array_key_last`, `array_keys`, `array_last`, `array_map`, `array_merge`, `array_merge_recursive`, `array_multisort`, `array_pad`, `array_pop`, `array_product`, `array_push`, `array_rand`, `array_reduce`, `array_replace`, `array_replace_recursive`, `array_reverse`, `array_search`, `array_shift`, `array_slice`, `array_splice`, `array_sum`, `array_udiff`, `array_udiff_assoc`, `array_udiff_uassoc`, `array_uintersect`, `array_uintersect_assoc`, `array_uintersect_uassoc`, `array_unshift`, `array_unique`, `array_values`, `arsort`, `asort`, `count`, `current`, `each`, `end`, `in_array`, `key`, `key_exists`, `krsort`, `ksort`, `natcasesort`, `next`, `natsort`, `prev`, `range`, `reset`, `rsort`, `shuffle`, `sizeof`, `sort`, `uasort`, `uksort`, and `usort`.
`iterator_to_array` and `iterator_count` accept arrays, generators, `PDOStatement`, and user `Iterator`/`IteratorAggregate` objects. `iterator_to_array` preserves keys by default, overwrites duplicate keys with the last value, and reindexes all values when `preserve_keys` is false. It retains reference-backed elements from array and generator inputs, including when values overwrite duplicate keys. `iterator_count` consumes the iterator. Nested `IteratorAggregate` results are followed. Built-in `Iterator` and `IteratorAggregate` correctly extend `Traversable` for `instanceof`, `is_a()`, `iterable` type checks, and `is_iterable()`; iterator edge cases and reference-aware traversal remain partial.

`array_pad()` keeps string keys, reindexes numeric-keyed source values in encounter order, and adds padding values at the left or right according to the sign of `length`. Existing reference cells remain connected in the padded copy. This follows the [PHP `array_pad()` manual](https://www.php.net/manual/en/function.array-pad.php).

Loose value matching in `in_array()` and `array_search()` uses the VM's PHP 8 comparison rules. For example, integer `0` matches numeric string `'0'` but not `'not numeric'`. Built-in value comparison in `array_diff()`/`array_intersect()` and their associative variants uses string representations, so numeric strings `'00'` and `'0'` remain distinct even though PHP considers them loosely equal. These comparisons use `__toString()` for Stringable objects, including default value checks in `*_uassoc()` functions; `*_udiff*()`/`*_uintersect*()` use their supplied value comparator. This follows the [PHP `array_diff()` comparison contract](https://www.php.net/manual/en/function.array-diff.php).

Strict nested-array matching in `in_array()` and `array_search()` requires keys in the same order as well as identical key/value types. Strict object, closure, generator, and stream matching uses instance identity; separately created values do not match. This follows the [PHP array operator identity rules](https://www.php.net/manual/en/language.operators.array.php) and [`array_search()` strict-mode contract](https://www.php.net/manual/en/function.array-search.php).

`foreach` traverses ordinary objects' public declared and dynamic properties outside class scope, and includes protected/private properties accessible from the active declaring-class scope. By-reference traversal writes back to the visible property slots. A user `Iterator` can also be traversed by reference when `current()` returns a reference; `IteratorAggregate` chains are followed, and iterators returning values rather than references fail with PHP's Error. Generators declared to return by reference can yield variable or array-element references into `foreach (&$value)`; `yield from` preserves yielded references from a reference-returning generator. Ordinary generators are rejected for by-reference foreach. Non-lvalue yields, by-reference delegation from other Traversable/array inputs, generator error-class/message parity, and further iterator edge cases remain incomplete. Invalid scalar/null foreach inputs emit a source-located, `error_reporting()`-filtered warning and skip the loop.

`shuffle()` and `array_rand()` select indices with rejection sampling over operating-system entropy. `shuffle()` reindexes the values as in PHP. `array_rand()` raises catchable `TypeError` for invalid array/count types and `ValueError` for an out-of-range count. These functions do not share PHP's seeded Mersenne Twister state, so `mt_srand()` reproducibility remains unsupported.

`array_map()` callback dispatch also supports the array utilities `array_combine`, `array_flip`, `array_key_exists`, `array_key_first`, `array_key_last`, `array_first`, `array_last`, `array_search`, `in_array`, `array_merge`/`array_merge_recursive`, `array_replace`/`array_replace_recursive`, `array_unique`, and the non-callback diff/intersection variants (`array_diff`, `array_intersect`, and their associative/key forms). `array_unique()` uses runtime string conversion for string comparison, including `__toString()`; warnings from `array_flip()` are forwarded to runtime diagnostics, as are warnings from `array_count_values()`.

`range()` dereferences scalar endpoints before selecting its numeric-string or byte-character behavior, so reference-backed decimal numeric strings and character endpoints follow the same paths as direct values. Numeric-string recognition trims PHP's ASCII whitespace set rather than Unicode whitespace, and the range regression checks a non-breaking-space prefix is treated as non-numeric. [`array_multisort()`](https://www.php.net/manual/en/function.array-multisort.php) raises `ValueError` for unknown sorting flags and `TypeError` when sort-order or sort-flag kinds repeat for one array. Emitting individual non-ASCII bytes remains incomplete because runtime strings currently require valid UTF-8.

`array_map`, `array_filter`, `array_reduce`, `array_all`, `array_any`, `array_find`, `array_find_key`, `array_walk`, `array_walk_recursive`, all callback-based diff/intersection variants, `usort`, `uasort`, and `uksort` accept named user-defined functions, public static method strings, closures, and two-item callable arrays containing a public object or class method. Implemented string and math builtins also dispatch as named callbacks; array utility callbacks include `count` (including `Countable` objects), `array_change_key_case`, `array_chunk`, `array_column`, `array_is_list`, `array_keys`, `array_product`, `array_reverse`, `array_slice`, `array_sum`, and `array_values`. `is_resource()` checks whether a mapped stream is still open. Other internal callback functions remain partial. `array_filter` supports `ARRAY_FILTER_USE_KEY` (key only) and `ARRAY_FILTER_USE_BOTH` (value then key); without a callback it applies PHP-like truthiness and ignores the mode. `array_walk` passes each top-level value by reference for function, closure, callable-array, and public static method-string callbacks, and ignores the callback return value; static method strings preserve this write-through argument as well. `count()` accepts arrays or objects implementing the built-in `Countable` interface and invokes the public `count()` method; `is_countable()` recognizes those same supported values and dispatches as an array callback. `Countable` declarations validate public instance visibility, no required parameters, and any declared `int` return type; recursive mode is limited to `COUNT_NORMAL` and `COUNT_RECURSIVE`, while invalid modes and non-countable values raise catchable `ValueError`/`TypeError`. `array_walk_recursive` does the same for leaf values in nested arrays, including nested arrays stored in reference cells; changes remain visible through aliases to those referenced arrays. Both write changes back to the input array. Callback-reference warnings are recorded for these callback APIs when function names, public static method strings, closures, object callables, or callable-array methods declare by-reference parameters. Warnings are emitted at callback invocation, so empty inputs, single-element user sorts, and comparator branches that never execute do not warn. For callback-based diff/intersection variants, each value/key comparator is diagnosed only if that specific comparator runs. Except for the writable value parameter of `array_walk` and `array_walk_recursive`, declared callback references bind to temporary arguments and do not modify the callback API's source arrays, even when the source slot contains an explicit reference. Comparator sorts and built-in descending sorts keep equal elements in their original order. Comparator results are coerced to numbers. `SORT_LOCALE_STRING` delegates NUL-free strings to the active process `LC_COLLATE` through `strcoll()`; embedded-NUL strings fall back to byte order, and PHP-level `setlocale()` is not implemented. `array_multisort()` uses the same string conversion path, including `Stringable` objects. `SORT_REGULAR` compares numeric strings using PHP's ASCII whitespace rules (not Unicode whitespace) and exact integer ordering when strings fit the signed integer range; nested arrays compare recursively by count and matching keys/values, and same-class user objects compare recursively by property key and value, independent of dynamic-property insertion order. `SORT_STRING`, `SORT_LOCALE_STRING`, and natural sort modes convert `Stringable` objects through `__toString()`; `array_unique()` applies the same conversion for its selected string comparison flag. Recursive regular comparisons throw a catchable `Error`. Key sort functions apply their requested sort flags, and `array_unique()` honors its `SORT_*` flag; PHP-level locale changes, differing-class/internal-object ordering, and other array comparison edge cases remain partial.

When `array_filter()` is called with `ARRAY_FILTER_USE_BOTH`, a callback declaring either value or key by reference receives temporary arguments: mutation does not change the source array or filtered result, and a callback-reference warning is recorded. This complements coverage for `array_walk()`/`array_walk_recursive()`, whose value argument is intentionally writable.

User comparator callbacks for the `array_diff*`/`array_intersect*` variants receive temporary value/key arguments. If the comparator requires references, a warning is recorded and its writes do not modify the input arrays. The `*_ukey` forms compare keys only; `array_udiff_ukey()` and `array_uintersect_ukey()` are project extensions rather than PHP standard functions.

`array_merge()` and `array_merge_recursive()` accept zero or more arrays and support the named variadic parameter `arrays`.

For `SORT_REGULAR`, objects from different user classes are treated as incomparable by the array comparator. Stable sorts keep their input order for such a pair, and `max()`/`min()` keep the first value when the comparison is tied. PHP documents different object classes as incomparable; internal classes with custom comparison handlers still need dedicated behavior.

## Still missing

### Array syntax and language behavior

- Reference cells in array slots support `=&` binding to variables or other array elements and remain shared across array copies; ordinary nested values separate when a copy is mutated. By-reference `foreach` over an array copy detaches ordinary slots from its source while preserving the loop variable's alias to the last visited element after the loop. Regressions cover multiple copies, embedded references, and the lingering foreach alias. Full behavior across every array builtin, general `Traversable` interaction, and PHP-compatible warning/notice/error levels remain unsupported.
- Full `array()` grammar and all key-casting overflow/edge rules.
- `range()` follows PHP 8.3's integer/numeric-string/byte sequence choices, supports decreasing ranges and negative steps for decreasing bounds, and uses only the first byte of multi-byte string endpoints. A float step with no fractional part is treated as an integer; a fractional float step selects float output. Zero/non-finite steps and non-finite endpoints raise catchable `ValueError`; arrays, objects, booleans, and null endpoints raise catchable `TypeError`. Runtime diagnostics cover empty endpoints, multi-byte nonnumeric bounds, nonnumeric strings implicitly converted beside numeric bounds, and float steps used for character ranges; the multi-byte warning says subsequent bytes are ignored. Warnings retain the canonical source file and callsite line for file-compiled programs. Since runtime strings require valid UTF-8, byte values that are not valid standalone UTF-8 are represented lossily as U+FFFD; exact diagnostic wording/version parity remains partial. See the [PHP `range()` manual](https://www.php.net/manual/en/function.range.php).

### Standard functions


## Compatibility caveat

Some supported functions simplify PHP's exact comparison rules, error behavior, sort flags, reference handling, or version-specific behavior. `pos()` aliases `current()` for direct, named-argument, and named callback calls. The runtime also currently exposes `array_udiff_ukey()` and `array_uintersect_ukey()`, which are not PHP standard functions, and `each()`, which was removed from PHP in 8.0; treat these as project extensions/legacy extras, not PHP 8.5 coverage. Before calling the array subsystem compatible, it needs a fixed target PHP version and broader comparison against PHP's official tests.


`SORT_LOCALE_STRING` now uses the active native collation locale for `sort()`, `asort()`, key sorts, `array_unique()`, and `array_multisort()`. The regression covers `Stringable` values through `array_multisort()`; locale setup within PHP remains unavailable because `setlocale()` is not implemented. See the [PHP sort manual](https://www.php.net/manual/en/function.sort.php).

`SORT_REGULAR` and the spaceship operator share the PHP-style array/object comparator. Arrays compare by size, then matching key/value pairs independent of insertion order; when the left array contains a key missing on the right, it compares greater. Arrays and objects compare greater than scalar operands, with objects greater than arrays. Recursive array/object comparisons throw catchable `Error`. The comparison ordering follows the [PHP comparison manual](https://www.php.net/manual/en/language.operators.comparison.php).
