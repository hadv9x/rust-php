# PHP array compatibility inventory

Increment/decrement operators on undefined variables emit a source-located `E_WARNING` and then apply the operator to the resulting `null` value (postfix therefore yields `null`; the variable is initialized to `1`). Increment/decrement of a missing key in an existing array also emits `Undefined array key` and creates that element with the resulting value; this applies to variable-rooted, instance-property, and static-property array paths. Booleans and decrement on `null` retain their values and emit PHP-compatible warnings. Decrementing a nonnumeric string (including the empty string) and incrementing a nonnumeric string emit deprecation diagnostics for the PHP 8.3/8.5 compatibility baseline; incrementing `null` converts it to `1`, while decrementing an empty string produces `-1`. `error_reporting()` filters these warnings/deprecations using `E_WARNING`, `E_DEPRECATED`, or `E_ALL`. Runtime diagnostics retain the active source file and line, which the CLI reports alongside the message. Unsupported array, resource, and object operands raise catchable `TypeError`. See the [PHP Manual](https://www.php.net/manual/en/language.operators.increment.php) and the [Saner Increment/Decrement Operators RFC](https://wiki.php.net/rfc/saner-inc-dec-operators).

This inventory is checked against the official [PHP array function reference](https://www.php.net/manual/en/ref.array.php), [array type documentation](https://www.php.net/manual/en/language.types.array.php), and [array operators](https://www.php.net/manual/en/language.operators.array.php). Compatibility is partial; implemented names do not imply every PHP edge case or warning is reproduced.

## Implemented syntax and behavior

- `[]` and `array()` literals, numeric and string keys, mixed keys, trailing commas, duplicate-key replacement, implicit numeric keys, and common PHP scalar key conversions.
- Array unpacking (`...$array`) with numeric keys reindexed and string keys preserved/replaced.
- Positional, literal-keyed, and nested destructuring with `list()` and short-array syntax, including skipped targets and implicit integer keys after explicit integer keys.
- Read and write nested offsets, append with `$array[]`, `$nested['key'][]`, and mixed nested append/key assignment paths (including committing appended nested paths rooted at `$GLOBALS`), keyed/unkeyed `foreach`, `unset()` on variables and offsets, and array union with `+`.
- By-value array copies; the VM updates the named variable for by-reference mutators.
- `array_column()` reads selected fields from array rows or public properties on object rows, preserves whole rows when `column_key` is `null`, and can index the output by another field.
- Ordinary reads of missing keys in an existing array now yield `null` and emit a filtered, source-located `E_WARNING` (`Undefined array key ...`). `isset()`, `empty()`, and `??` use silent offset reads. Nested by-value array copies separate ordinary nested values, while explicit reference cells embedded in arrays remain shared across copies. Mutation coverage is focused; full PHP copy-on-write/reference behavior across every array operation and warning path is not implemented.

## Implemented functions

`array_all`, `array_any`, `array_change_key_case`, `array_chunk`, `array_column`, `array_combine`, `array_count_values`, `array_diff`, `array_diff_assoc`, `array_diff_key`, `array_diff_uassoc`, `array_diff_ukey`, `array_fill`, `array_fill_keys`, `array_filter`, `array_find`, `array_find_key`, `array_first`, `array_flip`, `array_intersect`, `array_intersect_assoc`, `array_intersect_key`, `array_intersect_uassoc`, `array_intersect_ukey`, `array_is_list`, `array_key_exists`, `array_key_first`, `array_key_last`, `array_keys`, `array_last`, `array_map`, `array_merge`, `array_merge_recursive`, `array_multisort`, `array_pad`, `array_pop`, `array_product`, `array_push`, `array_rand`, `array_reduce`, `array_replace`, `array_replace_recursive`, `array_reverse`, `array_search`, `array_shift`, `array_slice`, `array_splice`, `array_sum`, `array_udiff`, `array_udiff_assoc`, `array_udiff_uassoc`, `array_uintersect`, `array_uintersect_assoc`, `array_uintersect_uassoc`, `array_unshift`, `array_unique`, `array_values`, `arsort`, `asort`, `count`, `current`, `each`, `end`, `in_array`, `key`, `key_exists`, `krsort`, `ksort`, `natcasesort`, `next`, `natsort`, `prev`, `range`, `reset`, `rsort`, `shuffle`, `sizeof`, `sort`, `uasort`, `uksort`, and `usort`.
`iterator_to_array` and `iterator_count` accept arrays, generators, `PDOStatement`, and user `Iterator`/`IteratorAggregate` objects. `iterator_to_array` preserves keys by default, overwrites duplicate keys with the last value, and reindexes all values when `preserve_keys` is false. `iterator_count` consumes the iterator. Nested `IteratorAggregate` results are followed. Built-in `Iterator` and `IteratorAggregate` correctly extend `Traversable` for `instanceof`, `is_a()`, `iterable` type checks, and `is_iterable()`; iterator edge cases and reference-aware traversal remain partial.

`shuffle()` and `array_rand()` select indices with rejection sampling over operating-system entropy. `shuffle()` reindexes the values as in PHP. `array_rand()` raises catchable `TypeError` for invalid array/count types and `ValueError` for an out-of-range count. These functions do not share PHP's seeded Mersenne Twister state, so `mt_srand()` reproducibility remains unsupported.

`array_map`, `array_filter`, `array_reduce`, `array_all`, `array_any`, `array_find`, `array_find_key`, `array_walk`, `array_walk_recursive`, all callback-based diff/intersection variants, `usort`, `uasort`, and `uksort` accept named user-defined functions, closures, and two-item callable arrays containing a public object or class method. Implemented string and math builtins also dispatch as named callbacks; `is_resource()` checks whether a mapped stream is still open. Other internal callback functions remain partial. `array_filter` supports `ARRAY_FILTER_USE_KEY` (key only) and `ARRAY_FILTER_USE_BOTH` (value then key); without a callback it applies PHP-like truthiness and ignores the mode. `array_walk` passes each top-level value by reference and ignores the callback return value; `count()` accepts arrays or objects implementing the built-in `Countable` interface and invokes the public `count()` method; `is_countable()` recognizes those same supported values and dispatches as an array callback. `Countable` declarations validate public instance visibility, no required parameters, and any declared `int` return type; recursive mode is limited to `COUNT_NORMAL` and `COUNT_RECURSIVE`, while invalid modes and non-countable values raise catchable `ValueError`/`TypeError`. `array_walk_recursive` does the same for leaf values in nested arrays, including nested arrays stored in reference cells; changes remain visible through aliases to those referenced arrays. Both write changes back to the input array. Callback-reference warnings are recorded for all these callback APIs when named functions, closures, or callable-array methods declare by-reference parameters. Except for the writable value parameter of `array_walk` and `array_walk_recursive`, declared callback references bind to temporary arguments and do not modify the callback API's source arrays. Comparator sorts and built-in descending sorts keep equal elements in their original order. Comparator results are coerced to numbers. `SORT_REGULAR` compares numeric strings using PHP's ASCII whitespace rules (not Unicode whitespace) and exact integer ordering when strings fit the signed integer range; nested arrays compare recursively by count and matching keys/values, and same-class user objects compare recursively by property key and value, independent of dynamic-property insertion order. `SORT_STRING`, `SORT_LOCALE_STRING`, and natural sort modes convert `Stringable` objects through `__toString()`; `array_unique()` applies the same conversion for its selected string comparison flag. Recursive regular comparisons throw a catchable `Error`. Key sort functions apply their requested sort flags, and `array_unique()` honors its `SORT_*` flag; locale-sensitive collation, differing-class/internal-object ordering, and other array comparison edge cases remain partial.

`array_merge()` and `array_merge_recursive()` accept zero or more arrays and support the named variadic parameter `arrays`.

## Still missing

### Array syntax and language behavior

- Reference cells in array slots support `=&` binding to variables or other array elements and remain shared across array copies; ordinary nested values separate when a copy is mutated. A regression covers multiple copies combining both rules. Full behavior across every array builtin, general `Traversable` interaction, and PHP-compatible warning/notice/error levels remain unsupported.
- Full `array()` grammar and all key-casting overflow/edge rules.
- `range()` follows PHP 8.3's integer/numeric-string/ASCII-byte sequence choices, supports decreasing ranges and negative steps for decreasing bounds, and truncates multi-byte ASCII endpoints to their first byte. Zero/non-finite steps and non-finite endpoints raise catchable `ValueError`; arrays, objects, booleans, and null endpoints raise catchable `TypeError`. Runtime diagnostics cover empty endpoints, multi-byte nonnumeric bounds, nonnumeric strings implicitly converted beside numeric bounds, and float steps used for character ranges; the multi-byte warning says subsequent bytes are ignored. Diagnostic location parity and non-ASCII byte strings remain incomplete. See the [PHP `range()` manual](https://www.php.net/manual/en/function.range.php).

## Compatibility caveat

Some supported functions simplify PHP's exact comparison rules, error behavior, sort flags, reference handling, or version-specific behavior. The runtime also currently exposes `array_udiff_ukey()` and `array_uintersect_ukey()`, which are not PHP standard functions, and `each()`, which was removed from PHP in 8.0; treat these as project extensions/legacy extras, not PHP 8.5 coverage. The `pos()` alias of `current()` is not implemented. Before calling the array subsystem compatible, it needs a fixed target PHP version and broader comparison against PHP's official tests.
