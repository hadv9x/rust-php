# Functions and calls

Function syntax is parsed in [`php-syntax/src/parser/functions/mod.rs`](../crates/php-syntax/src/parser/functions/mod.rs), represented by [`ast/functions/mod.rs`](../crates/php-syntax/src/ast/functions/mod.rs), compiled by [`php-compiler/src/codegen/declarations/functions/mod.rs`](../crates/php-compiler/src/codegen/declarations/functions/mod.rs), and executed by [`php-runtime/src/vm/functions.rs`](../crates/php-runtime/src/vm/functions.rs).

## Supported behavior

- `error_get_last()` returns the latest runtime warning/deprecation or user-generated notice/warning/deprecation as an associative array with `type`, `message`, `file`, and `line`, even when `error_reporting()` suppresses display. `error_clear_last()` clears it. `trigger_error()` and its `user_error()` alias support `E_USER_NOTICE` (the default), `E_USER_WARNING`, `E_USER_DEPRECATED`, and fatal `E_USER_ERROR` (deprecated since PHP 8.4 and stops execution with CLI status 255). `set_error_handler()` and `restore_error_handler()` support nested handlers, severity masks, and the four PHP 8 callback arguments; returning `true` handles the diagnostic, while falsey returns fall through to normal `error_reporting()` output. Exceptions thrown by a handler follow normal PHP `try/catch`; diagnostics raised inside a handler do not invoke it recursively and use the default reporting path. General fatal-error formatting remains incomplete.

- Top-level named functions, class methods, and anonymous closures with explicit by-value or by-reference captures.
- Generator functions and closures suspend lazily at `yield`, support explicit and automatic keys, retain loop/reference/exception state across resumes, and can be consumed by `foreach`. `Generator` supports `current()`, `key()`, `next()`, `rewind()`, `send()`, `throw()`, `valid()`, and `getReturn()`; its implemented methods bind named arguments using PHP parameter names.
- First-class callable syntax (`functionName(...)`, `$object->method(...)`, `ClassName::method(...)`, and callable arrays such as `[$object, 'method'](...)`) creates callable Closure objects. Named calls and by-reference arguments are forwarded, and `static::method(...)` retains late static binding. Method targets currently require public visibility.
- Positional parameters, scalar/nullable/class type hints, and scalar/class/nullable return types.
- Optional positional parameters with `null`, boolean, number, string, and negative-number literal defaults; defaults must follow required parameters.
- Variadic final parameters (`...$values`) on functions, methods, interface declarations, and closures; extra positional arguments are packed into an array and typed variadics validate each element. By-reference variadics (`&...$values`) retain references to positional and named arguments.
- Named arguments on user-defined functions, instance/static methods, constructors, and closures. Labels match parameter names case-sensitively, calls can reorder arguments, and omitted optional parameters use their defaults. Unknown names are collected by variadic parameters under their string keys; `__call()` and `__callStatic()` receive named arguments under their string keys too.
- Call-site argument unpacking (`...$iterable`) for functions, closures, constructors, and methods. Numeric keys become positional arguments, string keys become named arguments, and reference cells in unpacked arrays remain references. Arrays, generators, `PDOStatement`, and user `Iterator`/`IteratorAggregate` objects are materialized for unpacking. Repeated fixed or variadic named parameters, including duplicate string keys yielded by an iterator, report `Named parameter $name overwrites previous argument`. For user-defined functions and methods, Traversable values passed to by-reference parameters produce PHP's warning and are passed by value, including reference variadics. Common array mutators/sorters (including each array argument to `array_multisort()`), array-walk functions, and `similar_text()`'s percentage parameter also warn when supplied by Traversable unpack; any mutation stays on the temporary unpacked value. Other builtin reference signatures and edge cases remain incomplete.
- `call_user_func_array()` dispatches function-name strings (including built-ins), closures, two-item method callables, and objects with `__invoke()`. String keys in the argument array become named arguments; numeric keys remain positional, and reference entries are passed by reference.
- `call_user_func()` forwards positional and named arguments to function strings, built-ins, closures, callable arrays, static method strings, and invokable objects. Its arguments are passed by value, matching PHP; use `call_user_func_array()` to pass existing reference cells.
- `function_exists()`, `class_exists()`, `interface_exists()`, `method_exists()`, `property_exists()`, `get_class()`, `get_parent_class()`, `get_called_class()`, `is_a()`, `is_subclass_of()`, and `is_callable()` inspect user declarations and implemented built-ins; `function_exists()` consults the VM builtin signature inventory as well as array, math, string, and JSON dispatch inventories. `json_encode()` can also be used by name as an array callback, including for `JsonSerializable` objects. `property_exists()` sees declared inherited/private/static properties even when uninitialized or null, plus dynamic properties present on any object. `get_class()` and `get_parent_class()` preserve declared class spelling for user classes and use the current class inside methods when called without an argument. `get_called_class()` follows late static binding in methods and raises `Error` outside class context. `is_callable()` supports functions, closures, public instance/static methods, callable arrays, public `__invoke()` methods, and public `__call()` / `__callStatic()` handlers; its optional callable-name output is set for supported forms.
- `gettype()`, `get_debug_type()`, `is_int()` (and aliases), `is_float()` (and aliases), `is_string()`, `is_array()`, `is_countable()`, `is_iterable()`, `is_bool()`, `is_null()`, `is_object()`, `is_resource()`, `is_scalar()`, and `is_numeric()` provide common runtime type checks. Integer and floating-point literals, JSON values, and integer-preserving arithmetic retain distinct runtime types. Closures count as objects; no resource values are currently exposed. `is_countable()` returns true for arrays and instances of classes implementing the built-in `Countable` interface, including through inherited interfaces; `is_iterable()` recognizes arrays, generators, `PDOStatement`, and objects implementing `Traversable`. Both predicates work as array callbacks. Numeric strings are recognized, including surrounding whitespace and exponent notation.
- `intval()`, `floatval()`, `strval()`, and `boolval()` support direct calls and named `value:` arguments; `intval()` accepts `base:` 0 or 2 through 36, reads leading numeric digits, and recognizes `0x`/`0b` and leading-zero octal prefixes when base 0 is used. `intval` callbacks receive the mapped value and optional second-array base using the same prefix and base rules. `strval()` invokes `__toString()` for objects, including when used as an array callback. These functions are reported by `function_exists()`. PHP's full scalar coercion warnings and overflow edge cases remain incomplete. See the [PHP `intval()` manual](https://www.php.net/manual/en/function.intval.php).
- `file_exists()`, `is_file()`, `is_dir()`, `is_link()`, `is_readable()`, `is_writable()`, `is_executable()`, `filesize()`, `filemtime()`, `fileatime()`, `realpath()`, and `getcwd()` provide common local filesystem metadata and access checks. `filemtime()` and `fileatime()` return Unix timestamps or `false`, emit a source-located warning on failure, and support named `filename` arguments and callbacks. Unix access checks use the process credentials; non-Unix builds currently approximate readability/writability from metadata and report files as non-executable. `is_link()` inspects the path entry itself. Paths use the process working directory; full stream wrappers and script-relative path resolution are not implemented. See [`examples/filesystem-metadata.php`](../examples/filesystem-metadata.php).
- `stat()` and `lstat()` return the 13 standard file metadata fields under both numeric and named keys; `lstat()` inspects a symlink itself. Both are sandbox-confined, support named `filename` arguments and callbacks, and return `false` with a source-located warning on failure. Values are based on host filesystem metadata. See the [PHP `stat()`](https://www.php.net/manual/en/function.stat.php) and [`lstat()`](https://www.php.net/manual/en/function.lstat.php) manuals and [`examples/filesystem-stat.php`](../examples/filesystem-stat.php).
- `scandir()` returns `.` and `..` plus directory entries, sorted ascending or descending by default/constant, or in host enumeration order with `SCANDIR_SORT_NONE`. It supports named `directory`, `sorting_order`, and nullable resource `context` arguments, callback use, and `function_exists()`. Paths are sandbox-confined; failure returns `false` with a source-located warning. Stream-context behavior is not implemented. See the [PHP `scandir()` manual](https://www.php.net/manual/en/function.scandir.php) and [`examples/scandir.php`](../examples/scandir.php).
- `opendir()`, `readdir()`, `rewinddir()`, and `closedir()` use shared resource handles; the last opened handle is used when the optional handle is omitted. `readdir()` follows host enumeration order and returns `false` at end, `rewinddir()` rereads the directory, and `closedir()` invalidates all aliases. Explicit `null` handles emit the PHP 8.5 deprecation for `readdir()`, `rewinddir()`, and `closedir()`. `opendir()` paths are sandbox-confined and emit a source-located warning on failure. Stream-context effects remain incomplete. See the [PHP directory function manuals](https://www.php.net/manual/en/ref.dir.php) and [`examples/directory-handles.php`](../examples/directory-handles.php).
- `touch()` creates an empty file when needed and sets modification/access timestamps, with `atime` defaulting to `mtime`; it supports named arguments, callbacks, and `function_exists()`. Local paths remain confined to the configured filesystem root, and failures emit a source-located warning. See the [PHP `touch()` manual](https://www.php.net/manual/en/function.touch.php) and [`examples/filesystem-touch.php`](../examples/filesystem-touch.php).
- `chmod()` changes local file and directory modes on Unix; Windows only maps the owner write bit to its read-only attribute. It supports named arguments, callbacks, and `function_exists()`, and sandbox paths remain confined to the configured filesystem root. See the [PHP `chmod()` manual](https://www.php.net/manual/en/function.chmod.php) and [`examples/filesystem-chmod.php`](../examples/filesystem-chmod.php).
- `disk_free_space()`/`diskfreespace()` and `disk_total_space()` return filesystem byte counts for local paths on Unix. They support callbacks and `function_exists()`; unsupported platforms and failures return `false` with a warning. See the [PHP disk-space manuals](https://www.php.net/manual/en/function.disk-free-space.php) and [`examples/filesystem-disk-space.php`](../examples/filesystem-disk-space.php).
- `base64_encode()` encodes UTF-8 bytes and `base64_decode()` accepts the standard alphabet, ignores invalid characters by default, and returns `false` for invalid characters in strict mode. Whitespace is ignored in both modes; decoded non-UTF-8 bytes are lossy in this runtime. Both support named arguments, callbacks, and `function_exists()`. See the [PHP `base64_encode()`](https://www.php.net/manual/en/function.base64-encode.php) and [`base64_decode()`](https://www.php.net/manual/en/function.base64-decode.php) manuals and [`examples/base64.php`](../examples/base64.php).
- `md5()` returns the standard lowercase hexadecimal digest or raw 16-byte digest when `binary: true`; raw bytes outside valid UTF-8 are lossy in this runtime. It supports named arguments, callback dispatch, and `function_exists()`. See the [PHP `md5()` manual](https://www.php.net/manual/en/function.md5.php) and [`examples/hash-functions.php`](../examples/hash-functions.php).
- `sha1()` returns the standard lowercase hexadecimal digest or raw 20-byte digest when `binary: true`; raw bytes outside valid UTF-8 are lossy in this runtime. It supports named arguments, callback dispatch, and `function_exists()`. See the [PHP `sha1()` manual](https://www.php.net/manual/en/function.sha1.php) and [`examples/hash-functions.php`](../examples/hash-functions.php).
- `md5_file()` hashes the exact bytes of a local file and returns lowercase hexadecimal or raw digest output with `binary: true`. Paths are confined to the configured filesystem root, failures return `false` with a source-located warning, and raw output may be lossy for invalid UTF-8 bytes. Named arguments, callbacks, and `function_exists()` are supported. See the [PHP `md5_file()` manual](https://www.php.net/manual/en/function.md5-file.php) and [`examples/hash-functions.php`](../examples/hash-functions.php).
- `sha1_file()` hashes the exact bytes of a local file and returns lowercase hexadecimal or raw digest output with `binary: true`. Paths are confined to the configured filesystem root, failures return `false` with a source-located warning, and raw output may be lossy for invalid UTF-8 bytes. Named arguments, callbacks, and `function_exists()` are supported. See the [PHP `sha1_file()` manual](https://www.php.net/manual/en/function.sha1-file.php) and [`examples/hash-functions.php`](../examples/hash-functions.php).
- `htmlentities()` converts applicable characters from the HTML 4.01 named entity table, including the quote modes and `double_encode` option. It accepts UTF-8 only; HTML5-specific entity names, other encodings, and invalid-byte policies are not implemented. Named arguments, callback dispatch, and `function_exists()` are supported. See the [PHP `htmlentities()` manual](https://www.php.net/manual/en/function.htmlentities.php) and [`examples/html-entities.php`](../examples/html-entities.php).
- `get_html_translation_table()` returns the HTML 4.01 translation map for `HTML_SPECIALCHARS` or `HTML_ENTITIES`, with quote behavior controlled by `ENT_COMPAT`, `ENT_QUOTES`, or `ENT_NOQUOTES`. It accepts UTF-8 only and rejects XML/XHTML/HTML5 document flags; callback dispatch and `function_exists()` are supported. See the [PHP manual](https://www.php.net/manual/en/function.get-html-translation-table.php) and [`examples/html-translation-table.php`](../examples/html-translation-table.php).
- `html_entity_decode()` decodes HTML 4.01 named entities and decimal/hexadecimal numeric references, with quote flags and named arguments. It accepts UTF-8 only; XML/XHTML/HTML5 document flags and other encodings are unsupported. Callback dispatch and `function_exists()` are supported. See the [PHP manual](https://www.php.net/manual/en/function.html-entity-decode.php) and [`examples/html-entity-decode.php`](../examples/html-entity-decode.php).
- `filectime()`, `fileinode()`, `fileowner()`, `filegroup()`, `fileperms()`, and `filetype()` expose the corresponding metadata fields for sandbox-confined local paths. They accept named `filename` arguments and callbacks and return `false` with a warning on failure. Unix values use native metadata; non-Unix ownership, inode, and change-time values are limited by the host APIs.
- `basename()` extracts the final slash-delimited path component and optionally removes a matching suffix. `dirname()` returns one or more parent path components, defaults to one level, and throws `ValueError` for levels below one. These functions parse paths as strings and do not consult the filesystem; backslashes are treated as ordinary characters on this Unix runtime.
- `pathinfo()` returns the `dirname`, `basename`, optional `extension`, and `filename` fields, or a selected component through `PATHINFO_*` constants. The `PATHINFO_*` values are exposed to PHP and `flags:` is supported; extension detection uses the final dot, including dotfiles. Path parsing follows Unix slash separators and is not locale-aware.
- `stripcslashes()` decodes C-style single-byte, hexadecimal, and octal escapes, with named and callback dispatch. Output bytes that are not valid UTF-8 are converted lossily by the runtime.
- `strip_tags()` removes markup and HTML comments, optionally retaining tags named in the `allowed_tags` string. Named arguments and callback dispatch are supported. Its lightweight tag scanner does not validate HTML, reproduce PHP's malformed-markup parser, or model newer tag safety semantics.
- `ucfirst()` and `lcfirst()` change the ASCII case of the first character and leave the remainder unchanged. `ucwords()` applies the same ASCII-only capitalization after whitespace or caller-supplied separators. Non-ASCII letters are preserved because multibyte case conversion belongs to a separate extension-level API.
- `str_getcsv()` parses one CSV record into an indexed array, including quoted separators, doubled enclosure characters, caller-selected single-byte controls, and an empty escape string. Since PHP 8.4, omitting `escape` emits a filtered `E_DEPRECATED` diagnostic; pass `escape: ''` to disable the proprietary escape handling. Multibyte separators/enclosures and multi-character escapes raise `ValueError`; locale-specific single-byte encodings and other PHP diagnostics are not implemented.
- `hex2bin()` decodes pairs of hexadecimal digits into bytes and returns `false` with a source-located `E_WARNING` for odd-length or non-hex input. It is available as a named `string:` call, through `function_exists()`, and as an array callback. PHP strings are byte sequences; non-UTF-8 binary output is currently lossy because this runtime stores strings as UTF-8.
- `chr()` converts an integer modulo 256 into a one-byte character and complements `ord()`. Passing values outside `0..255` emits filtered `E_DEPRECATED` (PHP 8.5). Bytes that are invalid standalone UTF-8 are replaced because the runtime string representation is UTF-8; use ASCII-range values for lossless results.
- `count_chars()` counts byte values and supports PHP's five modes: full frequency table, used bytes, unused bytes, unique-byte string, and unused-byte string. Invalid modes throw `ValueError`. String modes follow the runtime's lossy UTF-8 limitation for byte values above ASCII.
- `func_get_args()`, `func_get_arg()`, and `func_num_args()` expose the active user-function or closure call's positional view and current parameter values. Named calls fill omitted parameters with defaults through the last specified parameter; positional variadic entries are included, while unknown named variadic entries remain available only in the variadic array, as in PHP 8+.
- `file_get_contents()` reads local filesystem paths and `php://input`, and supports named `offset` and `length` arguments for byte-range reads. `file_put_contents()` writes scalar, array, or stream data and supports `FILE_APPEND` and Unix `LOCK_EX`. `copy()` and `rename()` operate between sandbox-checked local paths, support named `from`/`to` arguments and array callback invocation, and emit filtered warnings when they fail. `mkdir()` creates local directories with a PHP-style mode and optional recursive creation; recursive paths are checked against the request's sandbox root. `rmdir()` removes empty local directories, including via array callbacks. Filesystem mutation helpers return `false` with a filtered warning when the operation fails. Optional contexts are type-checked but do not alter local-file behavior; arbitrary stream wrappers are not implemented. `fopen()` supports local files in `r`, `w`, `a`, `x`, and `c` modes as well as `php://temp` and `php://memory`; the returned streams work with `fread()`, `fwrite()`, seeking, and closing. `tempnam()`, `sys_get_temp_dir()`, and `unlink()` support temporary-file workflows. `set_include_path()`/`get_include_path()` maintain request-local lookup paths, honored by `file_get_contents(..., use_include_path: true)`, `fopen(..., use_include_path: true)`, and `file(..., FILE_USE_INCLUDE_PATH)`. Stream contexts and arbitrary stream wrappers are not implemented. File bytes are decoded lossily because runtime strings currently require valid UTF-8.
- See [`examples/filesystem-directories.php`](../examples/filesystem-directories.php) for recursive creation, mode handling, callback use, and directory cleanup.
- See [`examples/filesystem-rename.php`](../examples/filesystem-rename.php) for named local-path renames, callback dispatch, and cleanup.
- `file()` reads local files into an ordered array of lines. `FILE_IGNORE_NEW_LINES` removes trailing line endings, `FILE_SKIP_EMPTY_LINES` omits empty lines, and `FILE_USE_INCLUDE_PATH` searches the configured include path.
- See [`examples/filesystem-copy.php`](../examples/filesystem-copy.php) for named local-path copying, callback dispatch, and cleanup.
- `time()`, `microtime()`, and `hrtime()` provide Unix seconds, Unix seconds with microseconds, and monotonic high-resolution time. `microtime(as_float: true)` returns a float; `hrtime()` returns `[seconds, nanoseconds]` or a nanosecond integer with `as_number: true`. `date()`/`gmdate()` format common tokens; deprecated `strftime()`/`gmstrftime()` use the host C library's locale formatting and emit PHP 8.1+ deprecation diagnostics. `getdate()`, `localtime()`, `idate()`, `checkdate()`, `mktime()`, and `gmmktime()` provide calendar fields and timestamp construction. `strtotime()` parses ISO date/time strings with `Z` or numeric offsets and common relative words/units against an optional base timestamp. Local calendar operations use the host process timezone; PHP timezone configuration, broad natural-language parsing, and DateTime classes remain unsupported.
- `get_defined_vars()` returns the variables visible in the active local or global scope, resolving supported global/reference bindings. The global scope, `$GLOBALS`, function/method/constructor frames, closure captures, internally dispatched function callbacks, magic methods, and supported lifecycle hooks preserve insertion order; `$this` precedes method parameters. VM-only bookkeeping such as the late-static class slot is not exposed as a PHP variable.
- Recursive calls and return statements.
- By-reference parameters on named functions, methods, constructors, and closures; direct variable arguments share storage for the duration of the call. Functions, methods, and closures can return references to variables, nested array offsets, and public untyped instance properties; `=&` binds the caller to that cell. Alias assignment also accepts a public instance property or a call to a reference-returning function; unsupported sources are rejected at runtime.
- Instance, static, parent, and dynamic magic-method calls.
- Runtime argument and return type checks for implemented types. Weak-mode `int` and `float` parameters and return values coerce numeric scalars and numeric strings; integer variadics are converted element by element. Reference arguments and reference returns retain their referenced storage.
- Global constants can be declared with `define()` and read through constant expressions or `constant()`; `defined()` checks whether a supported constant exists. Built-in array flags such as `SORT_ASC`, `SORT_NUMERIC`, and `COUNT_RECURSIVE` are available.
- String helpers `strlen()`, `strtolower()`, `strtoupper()`, `ucfirst()`, `lcfirst()`, `ucwords()`, `trim()`, `ltrim()`, `rtrim()`, `str_repeat()`, `str_split()`, `strpos()`, `stripos()`, `strrpos()`, `strripos()`, `substr_count()`, `substr()`, `substr_replace()`, `explode()`, `implode()`, `htmlspecialchars()`, `htmlspecialchars_decode()`, `urlencode()`, `urldecode()`, `rawurlencode()`, `rawurldecode()`, `str_contains()`, `str_starts_with()`, `str_ends_with()`, `strstr()`/`strchr()`/`stristr()`, `strcmp()`, `strcasecmp()`, `strncmp()`, `strncasecmp()`, `strnatcmp()`, `strnatcasecmp()`, `str_increment()`, `str_decrement()`, `strrev()`, `strtr()`, `str_replace()`, `str_ireplace()`, `nl2br()`, and `wordwrap()` are available, including named arguments where the PHP signature supports them. URL helpers distinguish form encoding from RFC 3986 encoding; malformed percent escapes stay literal and invalid UTF-8 decoding is lossy. Stringable objects are converted through `__toString()` at the implemented string parameter positions. The two-argument replacement-map overload of `strtr()` does not support named arguments in PHP; named `string`, `from`, and `to` are supported for byte-wise translation. `str_replace()` and `str_ireplace()` process search/replacement arrays from left to right, support string or array subjects, and update their optional by-reference replacement count. `str_split()` splits by bytes and returns an empty array for an empty string; chunks that split a UTF-8 code point are lossily decoded because runtime strings are UTF-8. `str_repeat()` caps results at 16 MiB. `explode()` supports positive, zero, and negative limits; `implode()` supports both the one-array overload and separator/array form. `nl2br()` inserts `<br />` (or `<br>` when `use_xhtml` is false) before each `\r\n`, `\n\r`, `\n`, or `\r` sequence and preserves the original newline characters. `wordwrap()` supports configurable width, break strings, long-word cutting, named arguments, callbacks, and PHP's empty-break/zero-width `ValueError` cases; it uses byte positions, and cuts within UTF-8 sequences are lossy in this UTF-8-backed runtime. `substr_replace()` handles signed byte offsets and lengths, named parameters, callback use, and array inputs with per-element replacement/offset/length arrays; invalid UTF-8 cuts are decoded lossily. HTML escaping supports UTF-8, quote flags, `double_encode`, and common named/numeric entities. Case conversion, case-insensitive comparisons, and `str_ireplace()` currently compare ASCII letters only. String comparisons return only -1, 0, or 1; `strrev()` reverses bytes, so reversing multibyte UTF-8 may produce replacement characters. `strtr()` supports byte-wise character translation and longest-key-first replacement maps. `strstr()` and its `strchr()` alias return the matching suffix or the prefix when `before_needle` is true; `stristr()` does the same with ASCII case-insensitive matching. `strnatcmp()` and `strnatcasecmp()` compare digit runs numerically, reusing the array natural-order comparator. `strspn()`/`strcspn()` scan initial byte spans against character masks with offset/length support. `strpbrk()` returns the suffix beginning at the first byte found in a character mask, or `false` when there is no match. `str_word_count()` counts alphabetic words, returns a word list or byte-offset keyed list for formats 1 and 2, and accepts additional characters; recognition follows Unicode alphabetic characters. `str_increment()`/`str_decrement()` implement the PHP 8.3 ASCII alphanumeric helpers; empty strings, invalid characters, and decrement underflow throw catchable `ValueError`. `strrpos()`/`strripos()` search backward with byte offsets; `substr_count()` counts non-overlapping matches within an optional byte range. `trim()`, `ltrim()`, and `rtrim()` support character sets and `..` ranges. String offsets and lengths use byte positions; `strpos()` and ASCII case-insensitive `stripos()` return `false` when no match exists and reject offsets outside the string, while `substr()` returns an empty string for an offset beyond the end.
- `sprintf()` and `vsprintf()` format strings, while `printf()` and `vprintf()` write to script output and `fprintf()` writes to a stream. They share common string, integer, base-conversion, character, and floating-point conversions, positional arguments, fixed or `*`-supplied width/precision, custom padding characters, and alignment/sign flags; variadic forms accept named values and all forms support callback dispatch. Unsupported format specifiers and some argument diagnostics remain incomplete; full PHP formatting grammar is not implemented.
- `parse_str()` decodes form-style query strings into a required output array, including dotted/spaced variable-name normalization, nested bracket keys, append syntax, duplicate-key replacement, and named `result`; it does not mutate local variables from the query string.
- `substr_compare()` supports byte offsets (including negative offsets), optional length, ASCII case-insensitive comparison, named arguments and array-callback dispatch. It returns -1, 0 or 1; invalid offsets and negative lengths raise catchable `ValueError`.
- `strtok()` tokenizes by a set of delimiter bytes and retains its cursor between calls. Supply `string` and `token` to start or reset; subsequent calls pass only the delimiter. Consecutive delimiters and delimiters at the ends are skipped. The alternative one-argument call is positional because PHP does not support named arguments for that overload.
- `levenshtein()` calculates byte-based edit distance with optional insertion, replacement, and deletion costs. It supports PHP's named parameters and array-callback dispatch; multibyte UTF-8 characters are compared as bytes.
- `similar_text()` counts matching byte sequences recursively and can write the percentage to its optional third, by-reference argument. Argument order can change the count; two empty strings return zero. The function is available to array callbacks when called with two arguments.
- `json_encode()` and `json_decode()` support direct calls and named array-callback dispatch; `json_validate()` also supports named callback dispatch; `json_last_error()` and `json_last_error_msg()` can be invoked by callable name through `call_user_func()`. They operate alongside the runtime's scalar, array, and object values, nested values, escaped strings, Unicode surrogate pairs, and the default depth argument. Unpaired UTF-16 surrogates now report `JSON_ERROR_UTF16` (10), including the matching catchable `JsonException` code/message in throw mode. The decode/validate depth limit counts empty nested arrays and objects as structure levels. Regular objects encode public properties only, retaining declared order (including inherited declarations), followed by dynamic properties in insertion order, including properties first materialized through by-reference arguments; decoded objects and array-to-object casts retain input order. Objects implementing `JsonSerializable` are encoded from the return value of their public no-argument `jsonSerialize()` method. Encoding supports `JSON_PRETTY_PRINT`, `JSON_UNESCAPED_SLASHES`, `JSON_UNESCAPED_UNICODE` (Unicode is escaped by default), `JSON_FORCE_OBJECT`, `JSON_PRESERVE_ZERO_FRACTION`, `JSON_NUMERIC_CHECK`, `JSON_PARTIAL_OUTPUT_ON_ERROR`, `JSON_THROW_ON_ERROR`, `JSON_INVALID_UTF8_IGNORE`, `JSON_INVALID_UTF8_SUBSTITUTE`, and the four `JSON_HEX_*` flags; invalid-UTF-8 handling flags are no-ops for the runtime's valid UTF-8 strings. Decoding supports `JSON_OBJECT_AS_ARRAY`, `JSON_BIGINT_AS_STRING`, and `JSON_THROW_ON_ERROR`; omitted or null `associative` follows `JSON_OBJECT_AS_ARRAY`, while explicit `false` overrides that flag. With partial output enabled, non-finite numbers become `0`, unsupported values and recursive references become `null`, and `json_last_error()` retains the corresponding error code; this flag takes precedence over `JSON_THROW_ON_ERROR`. Otherwise the throw flag raises a catchable `JsonException` with the JSON error code, without changing the global JSON error state. Other flags are unsupported. Encoding failures return `false`, and decoding failures return `null` when throw mode is disabled. `json_last_error()` and `json_last_error_msg()` report success, depth, `JSON_ERROR_STATE_MISMATCH` for mismatched closing delimiters, syntax, non-finite-number, recursion, and unsupported-type errors; detailed UTF-8 and other exact PHP error classification remain incomplete.
- JSON parsing accepts only the four whitespace characters allowed by the JSON grammar: space, tab, carriage return, and line feed. Form feed and vertical tab outside a JSON string are syntax errors for both `json_decode()` and `json_validate()`.
- The built-in throwable hierarchy includes `LogicException` and its standard subclasses (`BadFunctionCallException`, `BadMethodCallException`, `DomainException`, `InvalidArgumentException`, `LengthException`, `OutOfRangeException`) plus `RuntimeException` and its standard subclasses (`OutOfBoundsException`, `OverflowException`, `RangeException`, `UnderflowException`, `UnexpectedValueException`). Native constructors accept positional or named `message`, `code`, and `previous` arguments. For programs loaded with `compile_file`, `getFile()` reports the canonical entry-file path and `getLine()` reports the line where a supported `new` expression creates the exception. Included-source attribution, call frames, and trace rendering remain unavailable.
- JSON serialization emits backed enum cases as their scalar backing values. Pure enum cases fail with `JSON_ERROR_NON_BACKED_ENUM` (11), or become `null` under partial-output mode; `JSON_THROW_ON_ERROR` raises `JsonException` with code 11. `JSON_INVALID_UTF8_IGNORE` and `JSON_INVALID_UTF8_SUBSTITUTE` are accepted by both encode and decode, but have no observable effect while strings remain valid UTF-8.
- `JSON_NUMERIC_CHECK` recognizes numeric strings with PHP's ASCII whitespace trimming; Unicode whitespace such as NBSP remains part of the string and prevents numeric conversion.
- `json_encode()` raises `ValueError` when its depth is less than 1, matching `json_decode()` and `json_validate()`; supported depths must fit the PHP integer range.
- `str_pad()` pads strings by byte length with left, right, or centered placement. The `STR_PAD_LEFT`, `STR_PAD_RIGHT`, and `STR_PAD_BOTH` constants are available; output is capped at 16 MiB, and partial UTF-8 pad bytes are lossily decoded.
- Date/time includes `date()` and `gmdate()` with named `format`/`timestamp` arguments, common calendar/time tokens, UTC formatting, and backslash-escaped literal characters; `getdate()` returns standard local-calendar fields, `localtime()` returns its nine numeric or associative `tm_*` fields, `gettimeofday()` returns seconds, microseconds, minutes west of Greenwich and DST status or a float, `idate()` returns integer date parts, `checkdate()` validates Gregorian month/day/year values, `mktime()`/`gmmktime()` normalize date components into timestamps, and `strtotime()` handles ISO date/time strings and common relative words/units against an optional base timestamp. Local calendar functions follow the host process timezone; PHP timezone configuration, timezone transition data, broader parsing, and DateTime classes remain incomplete.
- Deprecated `strftime()` and `gmstrftime()` use the host C library's locale-based formatting; they accept named `format`/`timestamp`, return `false` for empty/failed formatting, dispatch as callbacks, and emit source-located PHP 8.1+ deprecation diagnostics. See [`examples/time-functions.php`](../examples/time-functions.php); format support depends on the platform C library and process locale.
- On Unix, deprecated `strptime()` parses with the host C library and returns PHP's `tm_*` fields plus the unparsed suffix, or `false` when parsing fails. It accepts named `timestamp`/`format`, works through callbacks, and emits the PHP 8.2 deprecation message; parsing depends on libc and the process locale and is unavailable on Windows.
- Common math builtins include `abs`, `ceil`, `floor`, `round` (PHP 8.4+ rounding modes 1–8), `sqrt`, `fdiv`, `fmod`, `intdiv`, `exp`/`expm1`, `log`/`log10`/`log1p`, trigonometric and hyperbolic functions, `deg2rad`/`rad2deg`, `hypot`, finite/infinite/NaN predicates, scalar/array `min` and `max`, named-argument-aware `base_convert()` for bases 2–36 (values are limited to unsigned 128-bit magnitude), and `decbin()`/`dechex()`/`decoct()` for 64-bit integers. `number_format()` groups thousands, supports custom separators, and rounds half up including PHP 8.3 negative decimal counts. `random_int()` uses operating-system entropy, supports inclusive bounds and named arguments, and throws catchable `TypeError`/`ValueError` for invalid inputs. `rand()`/`mt_rand()` and `getrandmax()`/`mt_getrandmax()` support their common bounds/defaults using OS entropy; they do not reproduce PHP's seeded Mersenne Twister sequence. `shuffle()` and `array_rand()` also use OS entropy and unbiased index selection. `str_shuffle()` shuffles string bytes with OS entropy; invalid UTF-8 results are lossily decoded by the runtime's string representation. Other random and number-formatting functions remain unsupported; numeric coercion, object comparison, diagnostics, and floating-point edge behavior are not yet fully PHP-compatible.
- `addcslashes()` escapes caller-selected characters and `..` ranges, using C-style escapes for controls; it supports named arguments and array callback dispatch. `addslashes()`, `stripslashes()`, `str_rot13()`, `bin2hex()`, `ord()`, `chr()`, `hex2bin()`, and `crc32()` are supported. `crc32()` returns the unsigned 32-bit checksum as an integer; `bin2hex()` encodes UTF-8 bytes, `ord()` returns the first UTF-8 byte, and `chr()`/`hex2bin()` output is lossy for invalid UTF-8 bytes. PHP 8.5 deprecation diagnostics for multi-byte `ord()` input are not emitted. See the [PHP `crc32()` manual](https://www.php.net/manual/en/function.crc32.php) and [`examples/hash-functions.php`](../examples/hash-functions.php).
- `getenv()` reads an environment value, or returns the process environment merged with request-local `putenv()` values as an associative array when `name` is omitted or null. It supports named `name`/`local_only` arguments, `function_exists()`, and callback dispatch. `putenv()` sets a request-local `name=value` entry or removes an entry when given only its name; it supports callback dispatch and `function_exists()`. These values do not mutate the host process or `$_ENV`. Since the runtime exposes no separate SAPI environment store, `local_only` does not select a distinct source; invalid UTF-8 environment bytes are decoded lossily.
- Interface and override signature checks, including supported class variance.

## Current limits

- Parameter defaults support scalar literals, arithmetic/concatenation constant expressions, public named class/interface constants, `self::`/`parent::` constants in class scope, and nested constant array literals, including PHP-style canonical decimal-integer string keys. Each omitted argument receives a fresh array value. Array unpacking/references, function calls, and expressions involving variables remain unsupported.
- By-reference arguments and returns support simple variables, nested array offsets with computed keys, and public untyped instance properties. Typed, readonly, and inaccessible property references remain unsupported. Reference returns through static properties, magic properties, or non-lvalue expressions are unsupported.
- Named arguments are supported for the implemented string, math, array, JSON, filesystem, HTTP, date/time, session, MongoDB, selected introspection builtins, Generator methods, and enum `cases()`/`from()`/`tryFrom()` methods; parameter names/defaults still need a PHP-wide audit, and some internal class methods remain uncovered. `yield from` delegates arrays, generators, user `Iterator` objects, and nested `IteratorAggregate` results; sent values and injected exceptions are forwarded to delegated generators, and delegated generator return values are preserved. `finally` execution when a suspended generator is destroyed early is unsupported. `Generator::throw()` requires an object implementing the built-in or user-defined `Throwable` hierarchy and injects it through the suspended yield and VM catch/finally handlers. First-class callable syntax does not yet support private/protected method targets, even from a scope where PHP would allow them.
- `class_exists()`, `interface_exists()`, and `trait_exists()` invoke registered SPL autoload callbacks unless their `autoload` argument is false. `spl_autoload_register()` supports closures, callable arrays, invokable objects, prepend ordering, and the default namespace-to-file loader; `spl_autoload_extensions()` configures its suffix list. Dynamic loading depends on a source loader (available for compiled files/CLI execution), and exact SPL diagnostics and edge behavior remain incomplete. `function_exists()` only reports built-ins implemented by this runtime, not every function in PHP.
- Calling `func_get_args()`, `func_get_arg()`, or `func_num_args()` outside a user-defined function currently returns a runtime error; PHP emits a warning.
- `call_user_func()` keeps by-reference callback writes local but does not emit PHP's warning for passing a value to a by-reference parameter.
- `define()` does not support its case-insensitive mode. Only the built-in constants currently needed by implemented array and symbol-table functions are defined.
- JSON encode flags beyond `JSON_PRETTY_PRINT`, `JSON_UNESCAPED_SLASHES`, `JSON_UNESCAPED_UNICODE`, `JSON_FORCE_OBJECT`, `JSON_PRESERVE_ZERO_FRACTION`, `JSON_NUMERIC_CHECK`, `JSON_PARTIAL_OUTPUT_ON_ERROR`, and the four `JSON_HEX_*` flags, decode flags beyond `JSON_OBJECT_AS_ARRAY` and `JSON_BIGINT_AS_STRING`, detailed UTF-8 error classification, and exact PHP diagnostics are not implemented.
- Array callbacks support two-item public object-method or class-static-method callables. `array_walk` supports its first callback parameter by reference; other callback array functions do not. Callback array functions accept the forms listed in [array compatibility](array-compatibility.md).
- Basic union types are supported for parameters and returns, including weak numeric coercion and union-aware override/interface variance. Intersection and DNF types and full PHP variance rules remain unsupported.

## Adding a function feature

Keep the parser signature metadata and runtime `BytecodeFunction` metadata in sync. If the feature changes argument evaluation, update compiler expression/call generation as well as runtime dispatch, then add a runnable example.

- `var_dump()` prints scalar, array, and object values. For objects it calls `__debugInfo()` and prints the returned array instead of actual properties. This initial implementation uses a compact custom layout and marks cyclic references with `*RECURSION*`, but does not match PHP object IDs, resource details, or all reference formatting.
- `php_sapi_name()` reports `cli` for direct CLI execution and `cli-server` for the embedded HTTP server. `function_exists()` recognizes it; other SAPIs are not modeled.
